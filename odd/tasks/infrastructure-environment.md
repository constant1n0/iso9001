- **S5** — Selected «Condiciones por proceso + comprobaciones (Recomendada)»: «Para cada proceso, condiciones requeridas por factor (físico, social o psicológico) con criterio y frecuencia, y un historial inmutable de comprobaciones con resultado y evidencia.»
- Assumptions (not user requirements; follow the closest existing register, `EquipoMedicion`/`ComprobacionEquipo` in `app/services/equipment.py`, and its conventions):
  - Same permissions, attribution, audit, MCP and list-filter conventions as the equipment register (everyone reads; the roles that maintain equipment maintain these registers; list filters ignore unknown values; immutable history rows cannot be edited or deleted, web or MCP; cited rows protected with FK RESTRICT; retirement instead of deletion once history exists).
  - Responsible person: an active `Person` when chosen; historical links retained.
  - Frequency is free text (as in 7.4 plans); the next date is an explicit date. Recording an intervention/check requires an explicit new next date after it, applied to the parent in the same transaction (like 7.4 `CommunicationLog`), never recalculated. Dates in the future or before the latest entry are refused; retired elements/conditions take no new entries.
  - Intervention/check result: «conforme» / «no conforme»; a «no conforme» result requires the actions taken (text). The S4 NC citation is optional and only selectable on interventions; S5 checks have no NC citation (not requested).
  - Overdue next dates are flagged in the list (as for equipment) — no notifications.
  - Processes are `ProcesoOperacion`; an infrastructure element may support several processes (M2M); an environment condition belongs to exactly one process. `ProcesoOperacion.recursos` text stays unchanged.
  - Gap analysis 7.1 row and summary updated in the slice that closes it (T2); T1 updates the 7.1 row text only.
